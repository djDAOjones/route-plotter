# UI-03 — In-place parameter help

## Intent

Parameters need explaining where they are. The owner, 2026-10-05, relayed verbatim by the Backlog status session: "parameters need explaining somehow, ideally in situ i.e. hover over text on question mark, as some hard to know e.g. crowd emitter route bias", and later "I meant release bias". Today a pointer opens a parameter's hint only by a click (keyboard focus opens it too, hover never), although its dotted underline and help cursor suggest hovering; 58 of 133 controls have no hint, all 46 scene-outline fields among them; and some hints use words the panel does not show (Release bias never says which way is earlier). The owner placed it after Phase 1 ("After Phase 1 (Recommended)"). It is new feature work, which GATELESS-1's grant excludes ("no new feature work").

## Acceptance criteria

- A visible "?" beside each parameter's label opens its hint on hover after a delay, on keyboard focus and on tap, described to screen readers as today.
- Every parameter control has a hint in plain language, the scene outline's included, and each names the panel's own words.
- DEF-14's remedy is folded in: the hint has its own trigger, so a click on a label acts as a label.
- The UI standards and digests hold: WCAG 2.2 AAA targets, contrast and keyboard, Carbon productive.
