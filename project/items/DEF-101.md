# DEF-101 — Save can split a character across ZIP text chunks

## Intent

In v3 an ordinary Save Project can, rarely, lose text or write a file that will not reopen: the browser ZIP encoder can split a Unicode pair (a character outside the basic plane, such as an emoji in a label or an image name) across a 16,384-code-unit string chunk. The owner, 2026-11-18, ticked "Fix the save fault in v3" in the stock take: a v3 fix and a new zip for Xerte, the exception his freeze of v3 allows.

## Acceptance criteria

- A project whose text holds a character outside the basic plane at any chunk boundary saves and reopens with its text unchanged, through every save path.
- A test fails without the fix; no test is deleted, skipped or weakened.
- The fix is released as a new v3 build on the owner's call, and a new zip of it is made for Xerte.
- v4 passes the same check when it ports saving (MERGE-01's held list).
