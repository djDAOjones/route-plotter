# Nielsen's ten usability heuristics — digest

Ten rules of thumb for interface design, treated in this project as
hard rules rather than aspirations. Each line is a paraphrase; the
source carries the definitions and examples.

## Rules that bite here

1. Visibility of system status: the interface always shows what is
   happening, promptly.
2. Match between the system and the real world: words and concepts the
   user already uses, not the system's.
3. User control and freedom: an easy way out, undo and redo, for every
   action taken by mistake.
4. Consistency and standards: one meaning per word, one behaviour per
   control, platform conventions kept.
5. Error prevention: remove error-prone conditions and confirm before
   a destructive step.
6. Recognition rather than recall: options visible, nothing to
   remember between screens.
7. Flexibility and efficiency of use: shortcuts and customisation for
   the experienced without cost to the new.
8. Aesthetic and minimalist design: nothing on screen that does not
   earn its place.
9. Help users recognise, diagnose and recover from errors: plain
   language, the cause, and a way forward.
10. Help and documentation: task-focused, findable, short, and rarely
    needed.

## Checklist by task type

- Any control or flow: status shown (1); a way back (3); consistent
  with the rest (4).
- Destructive or costly actions: prevented or confirmed (5); errors
  explained with a fix (9).
- Screens and menus: recognisable choices, no memory load (6);
  nothing decorative (8).
- Power features: shortcuts that do not burden beginners (7).
- Copy: the user's words (2); help where the task is (10).

## Exceptions recorded

- none.
